# Contributing

Thanks for helping. Issues and pull requests are welcome, in English or German.

## Workflow

1. Work on a branch, never on `main`.
2. Keep commits small: one logical change each, with a message that says what and why.
3. Before you push, run:

   ```bash
   ruff check src tests && ruff format --check src tests && pytest
   npm test
   ```

4. Open a pull request. Someone else reviews it.

Python: type hints on every function, a docstring on every public function, a test for every new
function. Never type a number into the report or the website by hand: they come from
`gsw-eval report` and `gsw-eval site`.

## Add a model

1. Add an entry to `MODELS` in `src/gsw_eval/models.py`. An adapter needs `name`, `prompt_version`
   and `normalize(sentences)`, and returns the raw model text. `CachedNormalizer` stores and cleans it.
2. Pilot it: `gsw-eval run --model your-model --split dev --limit 20`.
3. Run it: `gsw-eval run --model your-model` and `gsw-eval run --model your-model --split ntrex`.
4. Run `gsw-eval report`, and commit `results/cache/your-model.jsonl` and `results/scores/`.

## Improve the texting rules

Rules live in `rules/texting_v*.tsv`, one per line: pattern, replacement, probability, note. A new
version needs a new run, because the inputs change.

## Data

No data and no API keys in git. Keys go into `.env`. The one exception is `site/data/`, which holds
the SwissDial test sentences for the website and is generated by `gsw-eval site`.
